# Серверная версия Drunken Guide

Один сервис обслуживает сайт и API с одного домена. GitHub Pages продолжает предоставлять локальные инструменты, но не аккаунты.

## Проверка на машине разработки

```sh
python3 -m venv .venv
.venv/bin/pip install -r server/requirements.txt
APP_ENV=development APP_ORIGIN=http://127.0.0.1:8001 .venv/bin/python server/app.py serve
```

Откройте сайт на порту 8001. База по умолчанию создаётся в игнорируемой папке `var`. В development cookie допускает HTTP. В production cookie Secure и нужен HTTPS.

## Docker на сервере

Укажите `APP_ORIGIN` как точный HTTPS-домен (без завершающего слеша), затем:

```sh
export APP_ORIGIN=https://your-domain.example
 docker compose up --build -d
```

Сервис привязан к 127.0.0.1:8001. Веб-сервер хостинга (Nginx/Caddy) должен завершать HTTPS и проксировать весь сайт, включая `/api`, на этот порт. Пример Nginx location:

```nginx
location / {
    proxy_pass http://127.0.0.1:8001;
    proxy_set_header Host $host;
    client_max_body_size 5m;
}
```

TLS-сертификат и домен настраиваются на хостинге. Не выставляйте Python-сервис в интернет напрямую. SQLite в Docker-volume `drunken-guide-data`; не удаляйте volume при обновлении. Для резервной копии используйте SQLite backup API или остановите сервис перед копированием базы (WAL-файлы нельзя игнорировать при обычном копировании живой базы).

## Первый администратор

Создаётся с терминала сервера. Пароль вводится скрыто, не хранится в Git и не передаётся аргументом команды:

```sh
docker compose exec web python server/app.py create-admin --email admin@example.com --name Администратор
```

Затем войдите на сайте и перейдите в `/admin.html`. Каждый admin API проверяет роль на сервере. Администратор может модерировать отзывы, блокировать и удалять пользователей, редактировать JSON-каталог и загружать фотографии. Загрузчик удаляет метаданные и перекодирует фото в JPEG; в каталоге указывается полученный `photo` (одно фото) или `stepPhotos` (массив по порядку шагов).

Новые рецепты доступны через `recipe.html?id=recipe-id`, поэтому не требуют генерации нового HTML-файла. При добавлении раздела энциклопедии потребуется отдельная страница по существующему шаблону.

## Что настроить до публичного запуска

- Домен, HTTPS, постоянное хранилище и резервное копирование.
- Контакты оператора и юридически проверенные документы для нужных стран. Текущие страницы документов — информационные заготовки с явной пометкой.
- Фото и права на них, редакционная проверка рецептов и замен; исходный каталог содержит 5 алкогольных и 3 безалкогольных рецепта. План на 100 коктейлей не является опубликованной базой.
- Отправка email, подтверждение адреса и восстановление пароля пока не реализованы. Не обещайте их пользователям. Google/Apple OAuth требуют отдельной интеграции и регистрации приложений.
- Аккаунты доступны без подтверждения email. Это отражено в интерфейсе. Перед массовым открытием регистрации рекомендуется добавить проверку email и дополнительную защиту от автоматической регистрации.

## Проверки

```sh
node tests/core.test.cjs
python3 -m unittest discover -s tests -p 'test_*.py'
```

Браузерная проверка: каталог и фильтры; выбор повода; сравнение; ингредиенты дома; общий список покупок; изменение порций; собственные рецепты; избранное; регистрация/вход; сохранение/загрузка аккаунта; отзывы и модерация. Для публикации на хостинге нужно повторить эти проверки по реальному HTTPS-домену.

## Сборка внутри среды с HTTPS-прокси

Если сборка выполняется в управляемой среде с собственным доверенным CA, Dockerfile принимает необязательный BuildKit secret `build_ca`. Передайте существующий доверенный CA-bundle этой среды:

```sh
docker build --secret id=build_ca,src=/etc/ssl/certs/ca-certificates.crt -t drunken-guide:local .
```

Bundle используется только для проверки TLS во время установки пакетов и не сохраняется в образе. На обычном хостинге достаточно стандартной сборки. Проверку TLS отключать не требуется.
